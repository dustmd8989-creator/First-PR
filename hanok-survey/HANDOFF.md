# 한옥 실측도 작성 작업 인수인계 (Handoff)

이 문서는 이전 대화에서 합의한 한옥 실측도 작성 작업의 범위, 방식, 입력 양식, 한계를 정리한 것입니다.
새 Claude Code 세션은 이 문서와 `survey_input_template.yaml`을 먼저 읽고 작업을 이어갑니다.

## 1. 작업 목표
- 현장에서 실측한 한옥의 치수, 구조 형식, 지붕 형태 정보를 받아 **2D 실측도(CAD 호환 DXF + 확인용 PNG/PDF)** 를 작성한다.
- 1차 목표: **평면도 1장**으로 표기 방식과 레이어 구성을 확정한 뒤, 입면도, 단면도, 지붕평면도, 가구(구조)도, 부재 일람표, 면적표로 확장한다.

## 2. 사용자 배경 (작업 관점)
- 사학, 고고학, 전통건축 학술연구자이자 건축사, 디자이너.
- 도면은 학술 보고서와 설계 실무 모두에 쓰일 수 있으므로 **실측값과 추정값을 반드시 구분**해 표기한다.
- 용어는 한옥 전통 용어(주심, 칸, 가구, 물매, 추녀, 공포 등)를 기본으로 하고, 필요하면 한자·영문을 병기한다.

## 3. 작업 환경 (이전 세션 기준)
- 클라우드 컨테이너(Linux), 저장소 `dustmd8989-creator/first-pr`, 작업 브랜치 `claude/claude-code-scope-encog4`.
- 컨테이너는 일시적이므로 **산출물은 커밋 후 푸시**해야 보존된다.
- 필요 라이브러리는 새 세션에서 다시 설치한다.

```bash
pip install ezdxf matplotlib
```

- DWG는 직접 생성하기 어렵다. **DXF**로 출력하고, 필요하면 사용자가 CAD에서 DWG로 저장한다.
- AutoCAD, Revit, Rhino 같은 GUI 프로그램은 직접 조작할 수 없다.

## 4. 작업 방식
1. 기준 도면(있다면)에서 레이어, 선 굵기, 치수 표기, 도면 틀을 읽어 같은 스타일로 맞춘다.
2. 실측 데이터를 `survey_input_template.yaml` 형식으로 구조화한다.
3. **입력 검증**을 먼저 수행한다.
   - 칸 간격 합계와 전체 길이 일치 여부
   - 대각선 폐합(직각 확인)
   - 기둥 높이, 처마 높이, 용마루 높이의 상호 모순
4. Python(`ezdxf`)으로 치수를 변수화한 **파라메트릭 스크립트**를 만든다. 실측값이 바뀌면 입력 파일만 수정해 모든 도면을 다시 생성한다.
5. DXF와 함께 PNG 미리보기를 만들어 사용자에게 보여 주고 수정 사항을 반영한다.
6. 완료한 산출물은 커밋하고 푸시한다. PR은 사용자가 요청할 때만 만든다.

## 5. 산출물 목록 (계획)
| 도면/문서 | 형식 | 비고 |
|---|---|---|
| 배치도 | DXF, PNG/PDF | 지적, 방위 포함(자료가 있을 때) |
| 평면도 | DXF, PNG/PDF | 칸 배열, 초석·기둥, 기단, 마루·온돌, 창호, 치수선 |
| 입면도 (정면/배면/좌우) | DXF, PNG/PDF | 지붕 물매, 처마, 높이 치수 |
| 단면도 (종/횡) | DXF, PNG/PDF | 가구 구성, 높이 치수 |
| 지붕평면도 | DXF, PNG/PDF | 맞배, 팔작, 우진각 등 |
| 가구도(구조도) | DXF, PNG/PDF | 3량, 5량, 7량, 서까래 배치 |
| 부재 일람표, 면적표 | XLSX, CSV | 도면과 연동 |

## 6. 도면 표기 원칙 (제안, 사용자 확정 필요)
- 단위: mm 기본, 영조척 병기 여부는 사용자가 결정.
- 권장 축척: 평면, 입면, 단면 1/50 (사용자 확정 필요).
- 권장 레이어(안):

| 레이어 | 내용 |
|---|---|
| A-GRID | 주심선, 칸 기준선 |
| A-COLS | 기둥, 초석 |
| A-WALL | 벽체 |
| A-DOOR / A-WIND | 문 / 창호 |
| A-PLAT | 기단, 마루, 온돌 구분 |
| A-ROOF | 지붕선, 처마, 추녀 |
| S-FRAM | 보, 도리, 서까래 등 구조 부재 |
| A-DIMS | 치수선 |
| A-TEXT | 실명, 주기 |
| A-EST | **추정 부분 (점선, 별도 색상)** |

- **실측 부분은 실선, 추정 부분은 점선과 주기**로 구분한다. 추정 근거는 주기 또는 별도 표에 적는다.

## 7. 한계와 주의
- 정확도는 입력 정보 수준을 넘을 수 없다. 임의로 채운 도면은 실측도가 아니라 **복원·추정도**다.
- 공포, 맞춤, 이음 같은 **상세 결구**는 단순화되기 쉽다. 상세도가 제공되면 그에 따라 작도한다.
- 스캔 이미지에서 치수를 읽을 때는 오차가 생길 수 있으므로 치수는 텍스트로 재확인한다.
- 구조 안전성 검토는 구조기술자의 확인이 필요하다.
- 문화유산 수리 보고서나 인허가용 제출 도면은 **건축사 검토와 날인**이 필요하다. 산출물은 작업용 초안이다.
- 샘플 수치로 만든 시범 도면은 도면 안에 **"가상 예시"** 라고 명시한다.

## 8. 현재 상태와 미확정 사항
- 저장소에는 기준 도면과 실측 자료가 아직 올라와 있지 않다. 작도는 시작하지 않았다.
- 사용자에게 아직 확인하지 못한 사항:
  1. 대상 건물 유형(민가, 사랑채, 정자, 전각 등)
  2. 실측 치수의 정리 상태(표인지 야장 사진인지)
  3. 기준 도면 유무와 형식(DXF, PDF, 이미지)
  4. 척도, 단위(영조척 병기 여부), 용지 크기
  5. 도면 틀 정보(건물 명칭, 소재지, 실측 일자, 작성자, 방위)
  6. 시범 작업을 샘플 수치로 먼저 할지 여부

## 9. 새 세션 시작 절차
1. 이 문서와 `survey_input_template.yaml`을 읽는다.
2. 저장소에 올라온 기준 도면과 실측 자료를 확인한다 (`hanok-survey/input/` 권장).
3. 위 8번의 미확정 사항 중 자료에서 확인되지 않는 것만 사용자에게 묻는다.
4. 입력 검증 결과를 보고한 뒤 평면도 초안(DXF, PNG)을 제출한다.
5. 사용자 확인 후 다른 도면으로 확장한다.

## 10. 권장 디렉터리 구조
```
hanok-survey/
  HANDOFF.md                   (이 문서)
  survey_input_template.yaml   (입력 양식)
  input/                       (기준 도면, 야장 사진, 실측표)
  scripts/                     (파라메트릭 도면 생성 스크립트)
  output/                      (DXF, PNG, PDF, XLSX)
```

## 11. 관련 논의 (참고)
이 대화에서는 다음 내용도 다뤘다. 필요할 때 별도 작업으로 이어갈 수 있다.
- 국토지리정보원 DWG 지형도 → DXF → SHP 변환: 좌표계(EPSG:5186 등) 확인이 핵심이며, 원본의 제작 연도와 도엽번호가 필요하다. 등록처(토지이음, 국가유산 공간정보서비스)별 규격은 공식 지침으로 확인해야 한다.
- 필지별 토지대장, 건축물대장, 등기부등본: 공공 API(건축HUB, 토지특성, V-World)는 인증키로 조회할 수 있다. 본인 인증과 결제가 필요한 발급은 사용자가 직접 하고, PDF를 올리면 분석·정리한다. 비밀번호와 인증서는 대화에 입력하지 않는다.
